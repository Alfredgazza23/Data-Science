# ML3 — валидация, отбор признаков и настройка моделей

Учебный проект по прогнозированию стоимости аренды. Задача — сравнить способы разделения данных, отбора признаков и подбора гиперпараметров.

[Открыть ноутбук](ML3_Validation.ipynb) · [Условие задания](README%20%2820%29.md) · [Все проекты](../README.md)

## Данные и подход

Используется набор [Two Sigma Connect: Rental Listing Inquiries](https://www.kaggle.com/competitions/two-sigma-connect-rental-listing-inquiries/data); целевая переменная учебной задачи — `price`.

После отбора по цене в рабочей выборке сохранено 48 379 объявлений. Исходный набор из 22 признаков включает характеристики квартиры и признаки из описания удобств.

## Что реализовано

- Собственные случайные и временные разбиения на две и три части.
- Реализации KFold, GroupKFold, StratifiedKFold и TimeSeriesSplit; сопоставление с разбиениями Scikit-learn.
- Сравнение схем кросс-валидации для Lasso по MAE, RMSE и R².
- Отбор признаков по коэффициентам Lasso, корреляции, permutation importance и SHAP.
- Сравнение полного набора из 22 признаков с сокращёнными наборами из 10 признаков.
- Настройка ElasticNet с помощью Grid Search, Random Search и Optuna/TPE.

## Сохранённые результаты

Пример сравнения Lasso на одной validation-выборке:

| Набор признаков | MAE | RMSE | R² |
|---|---:|---:|---:|
| Все 22 признака | 718,9936 | 1048,5029 | 0,5883 |
| Топ-10 по коэффициентам | 726,8185 | 1058,1222 | 0,5807 |

Сокращение этого набора признаков сопровождается небольшим ростом ошибки. В отдельном сравнении поиска параметров Grid Search использует 63 конфигурации, Random Search и Optuna — по 20 запусков.

Числа приведены из сохранённых выводов ноутбука и не пересчитывались при подготовке описания.

## Ограничения оценки

До разбиения удаляются наблюдения вне 1-го и 99-го процентилей цены. Полученные метрики относятся к отфильтрованным объявлениям. В экспериментах также неоднократно сравниваются результаты на test.

Для независимой итоговой оценки правила подготовки данных следует определять на train, выбирать признаки и параметры по validation/кросс-валидации, а test оставить для заключительной проверки. См. [рекомендации Scikit-learn по предотвращению утечек данных](https://scikit-learn.org/stable/common_pitfalls.html).
