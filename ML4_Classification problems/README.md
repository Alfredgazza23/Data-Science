# ML4 — классификация проблемных покупок автомобилей

Учебная задача — по данным об автомобиле и аукционной покупке предсказать, окажется ли покупка проблемной: `IsBadBuy = 1`.

[Открыть ноутбук](ML4_Classification%20problems.ipynb) · [Продолжение: деревья и ансамбли](../ML5_Decision_trees/README.md) · [Все проекты](../README.md)

## Данные

Набор [Don't Get Kicked!](https://www.kaggle.com/competitions/DontGetKicked/data): `training.csv`, **72 983 записи и 34 исходных столбца**, включая целевой. Доля положительного класса — около 12,3%.

Данные разделены по дате покупки `PurchDate`:

| Часть | Число записей |
|---|---:|
| Train | 23 059 |
| Validation | 24 104 |
| Test | 25 820 |

## Что реализовано

- Обработка пропусков, one-hot-кодирование категорий с небольшой мощностью, частотное кодирование остальных категорий и масштабирование. Параметры этих преобразований определяются на train.
- Обучение Logistic Regression, Gaussian Naive Bayes и KNN.
- Собственные реализации классификаторов и метрик на NumPy; сравнение с библиотечными решениями.
- Создание дополнительных признаков, отбор по коэффициентам и L1-регуляризации.
- Подбор гиперпараметров, исследование метрик и порога классификации при дисбалансе классов.

## Сохранённый результат

| Модель | Выборка | Метрика | Значение |
|---|---|---|---:|
| Базовая Logistic Regression | Validation | ROC-AUC | **0,736346** |

В резюме это значение округлено до **0,7363**. Оно относится к базовой модели и валидационной выборке.

## Ограничения оценки

- В блоке настройки порога используется `y_test`, включая поиск по F1. Поэтому результат этого поиска нельзя считать независимой тестовой оценкой: порог нужно выбирать на validation.
- Функция Gini в текущем коде берёт модуль выражения `2 * ROC_AUC - 1`. Для стандартного нормированного Gini нужно сохранять знак.
- Собственная реализация Average Precision требует проверки обработки одинаковых вероятностей, особенно для KNN.

Эти ограничения относятся к конкретным экспериментам и метрикам ноутбука. Приведённый выше ROC-AUC взят из сравнения базовой Logistic Regression на validation.
